PER-FIELD INSTRUCTIONS — read carefully before extracting.

unit_number / unit_id  (string | null, OPTIONAL)
  WHAT:  The visible unit/apartment number on the card.
  WHERE: A column "Unit"/"Apt", a tile heading, the first cell of a row.
  DO:    Copy the literal page value.
  DON'T: Return CSS class strings. Return null when no unit row is shown
         and only floor plans are listed.

floor_plan_name  (string | null, REQUIRED for every record)
  WHAT:  Human-readable plan name as shown.
  WHERE: Card heading, section title, or URL slug when nothing else is
         labelled. KNOWN FLOOR PLANS list above (when populated) is the
         canonical name set for this property.
  DO:    Prefer the canonical name from the KNOWN FLOOR PLANS list when
         beds + baths + sqft match. Otherwise use the page's literal label.
         If the page truly has no floor-plan label, fall back to the
         nearest section heading or URL slug and tag floor_plan_source.
  DON'T: Copy a canonical name onto a record whose beds/baths/sqft do not
         match. Don't return CMS module identifiers ("MODULE_*",
         "Lease Magnet", "Pop-Up", "Gravity FORMS"), vendor prefixes
         like "[Riedman]", or any guess.

floor_plan_source  (enum, REQUIRED when floor_plan_name is non-null)
  "page_label" | "section_heading" | "url_slug" | "inferred" | null.

bedrooms / bathrooms / sqft  (numbers)
  Studio = 0. Half-baths = 0.5. Strip commas + units from sqft.
  Never round, average, or output a range.

market_rent_low / market_rent_high  (numbers)
  For "$1,200 - $1,500" set low=1200, high=1500. Flat rent → both equal.

available_date  (YYYY-MM-DD or null)
  A concrete calendar date in YYYY-MM-DD form, derived from the page.
  TWO valid sources count as a date:

  (1) Page shows a printed date in any of these shapes — parse to ISO:
        "6/12/2026"        → 2026-06-12   (US slash, MM/DD/YYYY)
        "06/12/2026"
        "2026/06/18"       → 2026-06-18   (year-first slash)
        "2026-06-18"
        "6/12"             → 2026-06-12   (no year — use the next future
                                            occurrence: current year if
                                            the month/day is in the
                                            future, else next year)
        "7/24"             → 2026-07-24
        "June 12, 2026"    → 2026-06-12
        "Jun 12 2026"      → 2026-06-12
        "12 June 2026"     → 2026-06-12   (international ordering)
        "06.12.26"         → 2026-06-12   (dotted, two-digit year → 20xx)

  (2) Page shows a NOW-phrase that semantically means TODAY — set
      available_date to today's date AND copy the literal phrase to
      available_date_raw:
        "Available Now"         → today
        "Available"             → today  (bare badge — implies now)
        "Now Available"         → today
        "Now Leasing"           → today
        "Move-in Today"         → today
        "Move-in Ready"         → today
        "Immediate"             → today
        "Available Immediately" → today

  (3) Page shows a FUTURE-INDETERMINATE phrase that does NOT pin a date —
      set available_date to NULL and copy the phrase to
      available_date_raw:
        "Coming Soon"
        "Pre-Leasing"
        "Inquire" / "Inquire for availability"
        "Waitlist"
        "Contact for date"

  (4) Page shows no availability text or date at all → both fields null.

  Critical: never invent text in available_date_raw — only copy what the
  page actually shows. But available_date IS allowed to be derived
  (today's date for now-phrases, parsed ISO for printed dates).

available_date_raw  (string, REQUIRED when status is AVAILABLE OR when
                     any availability text is visible on the row)
  VERBATIM availability text COPIED FROM THE PAGE. Whitespace-collapsed,
  punctuation preserved. This is the AUDIT TRAIL for available_date —
  it tells downstream what the page actually said vs. what the model
  derived.
  Examples (all valid):
    "Available Now"            → available_date=today,  raw="Available Now"
    "Available"                → available_date=today,  raw="Available"
    "Now Available"            → available_date=today,  raw="Now Available"
    "Now Leasing"              → available_date=today,  raw="Now Leasing"
    "Move-in Today"            → available_date=today,  raw="Move-in Today"
    "Move-in Ready"            → available_date=today,  raw="Move-in Ready"
    "Coming Soon"              → available_date=null,   raw="Coming Soon"
    "Pre-Leasing"              → available_date=null,   raw="Pre-Leasing"
    "Inquire for availability" → available_date=null,   raw="Inquire for availability"
    "Available 6/12"           → available_date=2026-06-12,  raw="Available 6/12"
    "Available 7/24"           → available_date=2026-07-24,  raw="Available 7/24"
    "available 2026/06/18"     → available_date=2026-06-18,  raw="available 2026/06/18"
    "Available June 12, 2026"  → available_date=2026-06-12,  raw="Available June 12, 2026"
    "6/12/2026"                → available_date=2026-06-12,  raw="6/12/2026"
  Rules:
    1. Copy the WHOLE availability text segment as it appears on the
       page — the verb + the date if both are present.
    2. Preserve the page's original casing.
    3. Whitespace-collapse only (single spaces between words).
    4. Strip surrounding tag chrome (≪Available≫ → "Available").
    5. Never invent text. If the row has zero availability indication
       AND no concrete date, set raw to null.
  Use this field to PROVE provenance: any downstream auditor can see
  whether the date came from a printed date, a now-phrase, or a guess.

availability_status, availability_count

amenities, concession_text, concession_value, concession_source

           - "strikethrough_dom" : strikethrough pricing in the DOM
           - "description_text"  : prose mention in a description
           - "specials_section"  : dedicated specials/promotions block
  DON'T: Fabricate. Don't infer concessions from rent-range bottom anchors.
